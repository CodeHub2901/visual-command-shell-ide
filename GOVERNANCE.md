# Governance

Command IDE is currently maintainer-led while the contracts and Linux beta are
stabilized.

Maintainers merge changes, publish releases, handle security reports, and
appoint additional maintainers based on sustained, constructive contributions.
Substantial changes to trust boundaries, public schemas, supported shells, or
release scope require an architecture decision record and maintainer review.

Routine decisions use lazy consensus in the relevant issue or pull request.
Security fixes and release blockers may be handled privately until disclosure
is safe. If consensus cannot be reached, active maintainers decide by simple
majority; a tie leaves the current behavior unchanged.

Project conduct is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
Vulnerabilities follow [SECURITY.md](SECURITY.md). Governance changes use the
same public review process as source changes.
