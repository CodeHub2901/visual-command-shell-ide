# Architecture guide

The application is offline-first and split into three trust domains:

```text
Sandboxed React renderer
        |
        | frozen, validated preload methods
        v
Electron main process
        |
        | Content-Length framed JSON-RPC on private stdin/stdout
        v
Bundled Java 21 worker
        |
        +-- catalog, manuals, system detection, generation, risk
        +-- SQLite projects/bookmarks/history/settings
        +-- canonical import/export and Bash syntax validation
        +-- PTY execution and redacted history
        +-- passive tool detection and owned Bash Language Server process
        +-- proposal-only Ollama and OpenAI adapters
        +-- OS credential stores with session-memory fallback
```

There is no localhost HTTP server. The renderer has no Node integration and
cannot spawn a process. Electron blocks arbitrary navigation, new windows, and
webviews. Every public payload is parsed by Zod in preload/main and validated
again by the Java dispatcher/domain service.

## Implemented request flow

1. `v1.system.detect` returns a normalized host, distro, shell, architecture, and
   bounded PATH profile.
2. `v1.catalog.search` returns schema-versioned bundled metadata and passive
   executable availability. Search never runs a command.
3. `v1.catalog.discover` scans bounded PATH directories without launching or
   reading binaries, preserves PATH precedence, deduplicates names, filters
   control-character filenames, enriches catalog matches, and caches the
   inventory until an explicit refresh. Truncation and shadowed-name counts are
   part of the response rather than hidden.
4. `v1.catalog.probeVersion` is an explicit action. It runs only an absolute
   discovered executable with catalog-allowlisted arguments, bounded output,
   deadline, process-tree cleanup, sanitization, and caching.
5. `v1.manual.get` tries an absolute `man`, then the catalog executable's
   `--help`, then bundled text. Native output is untrusted bounded text and is
   never inserted as HTML.
6. `v1.shell.parse` maps the deliberately supported Bash subset to ShellProgram
   1.4 nodes with source spans, including assignments, exports, whole-word
   variable references, recursively nested groups/subshells, functions,
   conditionals, `for`/`while`/`until` loops, and typed `case` arms with
   literal or portable glob patterns.
   Unknown or ambiguous syntax is returned as exact
   raw code with bounded diagnostics, never silently discarded.
7. `v1.shell.generate` validates a versioned `ShellProgram` against catalog
   arguments/options and generates canonical Bash with deterministic quoting and
   metadata-authorized flag compaction.
8. `v1.risk.assess` regenerates the script, returns rule evidence, and creates a
   SHA-256 hash of the exact reviewed Bash.
9. `v1.projects.save/get/list` stores only the versioned project AST, target,
   parameters, and layout. Java regenerates it before save and rejects detected
   embedded credentials. Review hashes and approvals are deliberately excluded.
10. `v1.projects.import` applies the same bounded parsing, legacy migrations,
    structural validation, regeneration, and secret rejection without silently
    storing the imported project.
11. `v1.export.create` produces canonical project JSON, Markdown recipes, or
    Bash. Bash export supplies the exact generated bytes to an absolute
    discovered Bash with `--noprofile --norc -n`; a missing, broken, timed-out,
    truncated, or nonzero validator prevents the artifact from reaching a save
    dialog.
12. Electron main owns native open/save dialogs and exposes no renderer method
    that accepts a path. Imports are regular `.cmdbuilder.json` files bounded to
    2 MB. Exports use a bounded same-directory temporary file, flush, and atomic
    rename, while preload and main validate every IPC payload and result.
13. Electron main owns the native working-directory chooser and maps its result
    to a bounded opaque token. `v1.execution.start` resolves that token before
    Java receives an absolute directory; no renderer execution method accepts a
    raw path.
14. `v1.execution.start` independently regenerates and reassesses the supplied
    `ShellProgram`, exact-compares the reviewed script and hash, enforces
    Guided/Compact confirmation policy, and starts an absolute discovered Bash
    through the Maven-managed Pty4J adapter. Output, input, resize, cancel,
    error, and exit use framed notifications; session count and output volume
    are bounded, and shutdown/cancel clean up the process tree.
15. The lazy xterm view sends keystrokes directly to the narrow execution API
    without storing them in React state. A stateful output filter removes every
    OSC sequence, including sequences split across worker chunks, while
    retaining ordinary ANSI/CSI rendering. `v1.history.list` returns only
    timestamped status, working directory, and centrally redacted command text.
16. `v1.bookmarks.save/list/delete` persists a versioned structured selection:
    `ShellProgram`, parameter metadata, name, ID, and timestamps. The renderer
    derives missing metadata only from typed variable/redirect nodes; Java
    regenerates the program, rejects embedded credentials and secret defaults,
    and never stores rendered-only command text or execution approval.
17. `v1.tooling.detect` reports the bundled Bash Language Server separately
    from optional system ShellCheck/shfmt executables. Passive detection never
    launches a PATH executable. The Settings workspace exposes localized
    bundled/system/missing provenance and trusted-source installation guidance
    but has no installation capability.
18. `v1.language.open/change/close/completion/hover/symbols/references` is a narrow session API.
    Electron supplies its executable as an embedded Node runtime plus the
    exact `bash-language-server@5.6.0` CLI entrypoint. Java validates the
    absolute launch paths, prefers that bundled command, and retains a trusted
    absolute PATH fallback for development. It uses a fixed `start` argument,
    an allowlisted environment, 4 MiB LSP frames, five-second request
    deadlines, and bounded document/session counts. ShellCheck, shfmt, and
    background-workspace subprocesses are disabled inside the server; the
    explicit Java-owned optional-tool APIs remain the only such actions. Java owns
    initialize/didOpen/didChange/didClose/shutdown/exit and handles only a small
    safe set of server-to-client requests. `v1.language.diagnostics`
    notifications contain normalized positions and text rather than raw LSP.
    Symbols and references are restricted to the active in-memory document;
    arbitrary server-provided file URIs never cross into Electron.
    If startup or a request fails, Monaco keeps its bundled catalog providers.
19. `v1.tooling.shellcheck` and `v1.tooling.shfmt` are explicit actions that
    supply source over bounded stdin to absolute detected executables with fixed
    arguments, a five-second deadline, a secret-free allowlisted environment,
    process-tree cleanup, and bounded output. ShellCheck output becomes
    normalized markers. shfmt output remains a preview until an explicit Apply.
20. `v1.ai.models/test/probe/propose` is a proposal-only provider boundary.
    Ollama defaults to loopback, enumerates only installed models, never installs
    or downloads, rejects unconfirmed remote endpoints and non-HTTPS remote
    transport, and uses bounded non-streaming structured JSON requests. Java
    rejects embedded credentials, requires model capability probing, validates
    the provider envelope, runs the normal parser/generator/local Bash syntax
    checker/risk service, and returns no execution identifier or authority.
    The renderer may copy a validated proposal into a new unsaved editor draft;
    execution remains a separate reviewed workflow.
21. `v1.credentials.status/store/delete` exposes write, delete, and metadata-only
    operations for the OpenAI key. Java owns Windows Credential Manager, macOS
    Keychain, and Linux Secret Service access. If the selected secure backend is
    unavailable or locked, the key exists only in zeroized worker-session
    memory. It never enters SQLite, project JSON, logs, or a renderer read API.
22. OpenAI requests use only `https://api.openai.com/v1`, the official Java
    Responses client, typed Structured Outputs, `store=false`, bounded timeouts,
    zero automatic retries, and a stable random safety identifier. Provider
    refusals and malformed responses fail closed into review-only states.

## Implemented editor flow

- Guided option/argument edits replace the selected command node inside the
  existing recursive `ShellProgram`; sibling commands, control flow, comments,
  and raw nodes are retained rather than flattened.
- A pure AST-to-graph projection feeds React Flow. All modeled node kinds are
  visible, nested relationships are labeled, and draggable positions plus the
  viewport are stored in the project layout.
- Compact mode lazy-loads Monaco's ESM editor API and only the Shell language
  contribution. Its editor worker is bundled inline; the CSP permits local/blob
  workers but still denies network connections and non-local scripts.
- Monaco registers local catalog completion and hover providers. When the
  bundled Bash Language Server is connected, its normalized completion,
  hover, symbol, and same-document reference results are merged ahead of those
  deterministic fallbacks. Command
  suggestions use the unfiltered bundled catalog; option snippets are
  metadata-derived and omit flags already present in the active command.
  Parser source spans and version-filtered server/explicit-ShellCheck
  diagnostics become inline Monaco markers; equivalent external diagnostics
  are deduplicated without rewriting source.
- Guided generation and Compact parsing share an in-memory draft. Switching
  modes does not require saving and does not send source outside the private
  Electron-to-Java channel. A visual edit canonicalizes supported syntax; merely
  opening Guided mode does not overwrite the exact Compact draft.
- React Flow exposes semantic edits rather than mutating its projection directly.
  Catalog examples are parsed through Java and cloned with fresh recursive IDs;
  comments can be inserted; top-level handles create newline, pipeline, or
  Boolean relationships only when the AST operand types permit them; recursive
  deletion collapses one-child operators and refuses an empty root program.
  Every accepted edit regenerates and reassesses through the normal worker path.
- Shared project actions are outside the mode-specific editor. Guided and Compact
  therefore save or export the same synchronized AST and layout rather than
  maintaining independent copies.
- Bookmarks reuse the synchronized draft without flattening it. Reopening creates
  a new unsaved project with the bookmarked AST and parameters, leaving the
  original bookmark immutable until an explicit save or delete action.

## Data ownership

- Versioned contracts and JSON schemas: `packages/contracts`.
- Renderer and IPC boundary: `apps/desktop`.
- Authoritative local capabilities and SQLite: `apps/worker`.
- Bundled command pack: `apps/worker/src/main/resources/catalog`.
- Maven-built Java runtime image: `apps/worker/target/runtime` (generated).
- User-facing roadmap: `outputs/implementation-plan.md`.

Architecture decisions live in `docs/adr`. The command metadata invariants are
documented in `docs/architecture/command-pack-schema.md`; current abuse cases are
tracked in `docs/architecture/threat-model.md`. Primary-source package evidence
for exact overlay differences is recorded in
`docs/architecture/catalog-version-evidence.md`. Automated regression ceilings
are recorded in `docs/architecture/performance-budgets.md`; native build and
packaged-runtime verification are documented in `docs/release/building-linux.md`.
The typed shared UI catalog, locale selection, fallback, plural, and formatting
rules are documented in `docs/architecture/localization.md`.
